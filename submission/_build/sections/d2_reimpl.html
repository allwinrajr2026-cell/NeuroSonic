Re-implementation of the Base Paper

What was released, and its state

The public repository contains five parts: data collection with the CS30 SDK, the reinforcement-learning compression, the FPGA design, the smartphone deployment, and the cross-modal detector with its training run exp72. Code and data are distributed through nine Google Drive links. We inspected the detector code, the checkpoint and the published dataset in detail and, for the other links, read the archive indexes without downloading the whole archives.

The detector scripts did not run with current libraries. We found:

  • the training, validation and detection scripts call the model with one concatenated input, whereas its forward function expects two separate tensors (NIR and depth);
  • use of NumPy aliases that have been removed (np.int) and of PyTorch loading defaults that have changed;
  • a missing clouddir argument in one code path, and a detection script that exits before non-maximum suppression;
  • no saved results file and an empty TensorBoard log for the reported run; only the training plots remain.

Modifying the original repository would have made comparison impossible, so it was left untouched and a separate, standalone inference package was written.

Faithful re-implementation

The package (woad/) has three parts. A loader reads the pickled checkpoint by temporarily mapping the original module names to vendored copies of the nine classes the checkpoint needs. It checks the file's SHA-256 hash and the module tree, and it refuses a second, incompatible five-class checkpoint found at the repository root. A preprocessing module reproduces the original validation pipeline: the NIR image is resized so that its long side is 640 pixels (area interpolation) and letter-boxed to 640×640; the depth image is median-filtered (3×3) and letter-boxed; both are converted to RGB channel-first tensors in [0, 1]. The detector applies the original non-maximum suppression and coordinate scaling, so its detections are in the original image coordinates.

Equivalence test. A tool runs the original model code in a separate process and our re-implementation on the same seeded inputs and compares the raw outputs. The maximum absolute difference is 0.0: the re-implementation is bit-identical to the original.

Modality ablation. To confirm that both inputs matter, we measured the total detection confidence when inputs are altered. Swapping NIR and depth leaves 8 % of the confidence; blanking the NIR input removes all detections; blanking the depth input leaves 65 %. Both modalities are used, and NIR dominates. Automated tests encode these properties, and deliberately breaking the preprocessing makes them fail.

Dataset audit

The detector's published data (VOCdetiv_data.rar, 1.31 GB) was downloaded, its size checked against the server and its RAR checksums verified. It holds four nested variants with 4 to 10 classes; the largest (nc_10) has 1,286 training and 365 validation image pairs with classes such as person, box, bike, zebra crossing, telegraph pole, doors, building entrance and traffic signs. The audit found that this is not the dataset behind the reported run:

  • the checkpoint's classes are person, Ebike and Car; the dataset has no Ebike or Car class;
  • none of the run's 187 validation frames (recovered from the run's plots) appears among the dataset's 1,651 unique images: the best normalised-correlation similarity was 0.72, while the same matcher recovers deliberately degraded dataset frames at above 0.9;
  • dates and file paths in the archive differ from those of the run.

We also checked the other Drive links. The code bundle, two unlabelled recordings and the SDK do not contain the labelled person/Ebike/Car data either; one link returns HTTP 404. Other data issues: one orphan label, 53 file names reused between training and validation with different pixels, and one class ("Down stairs") without instances.

Evaluation method

The only class shared by model and data is person, so the evaluation is a cross-dataset person measurement. The evaluation tool reproduces the original validation settings exactly ({{t-evalmethod}}). Its AP code was verified to give identical values to the original code on random data.

{{t-woadres}} gives the results; precision (P) and recall (R) are at the maximum-F1 operating point (confidence 0.18 on val, 0.33 on train). {{f-pr}} shows the precision–recall curves. At the original plotting settings (confidence 0.25, IoU 0.45) the model detected 37 of 129 people in the validation split and missed 89, with 5 unmatched detections; in the training split it detected 104 and missed 345. The forward pass took about 126–131 ms per image on the CPU in batches of 8.

Interpretation. {{f-repvsmeas}} contrasts the reported person AP (0.771) with our measurement (0.218 val, 0.173 train). Because the datasets differ, the gap measures generalisation to new scenes, not an error in the paper. The model is fairly precise but misses most people in these scenes. Visual inspection of sampled frames showed that close, upright people are detected with high confidence (0.74–0.87), whereas cyclists and distant people indoors are usually missed. The bicycle class of the dataset scored essentially zero as "Ebike", which is expected given the different class definitions and is not reported as an accuracy figure.

Brightness and live-input experiment

A raw CS30 recording released with the repository is much darker than the training-like data (mean NIR brightness 59 versus about 140). Darkening training-like frames to that level removed about 73 % of detections, and histogram correction of the dark recording produced one correct detection and 56 false alarms. The model is therefore sensitive to sensor exposure, which motivated an input-quality gate in our implementation that flags frames that are too dark, too low in contrast, or almost without valid depth, and withholds alerts from unusable frames.

Re-use of the base model in this project

The re-implemented detector is kept in the project as a research path: a command-line tool and a "replay" mode run it on recorded NIR + depth sequences, with an alert engine that requires confirmation over several frames, applies cooldowns and states the object position (left, ahead, right). Thirty-eight original-equivalence and model tests remain part of the automated suite.
