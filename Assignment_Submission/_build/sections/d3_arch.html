System Architecture

Deployment

The server is a standard-library Python HTTP(S) server on the laptop. The phone loads a web application (HTML, CSS and JavaScript) from it; nothing is installed on the phone. Safari grants camera and microphone access only to secure pages, so the server uses HTTPS with a certificate issued by a locally generated certificate authority. The user installs the authority once from a plain-HTTP setup page on the next port; browser security is never disabled. The deployment architecture is shown in {{f-proparch}} and the per-frame pipeline in {{f-pipe}}.

Phone client

  • Posts a 320-pixel-wide JPEG every 200 ms (400 ms if the laptop reports the CPU detector), with at most one request in flight, so a slow answer reduces the frame rate instead of building a queue.
  • Records speech as WAV for command recognition when the user presses the talk button.
  • Uses GPS locally and sends a position only to request a route.
  • Plays speech through a priority queue (urgent > system > obstacle > navigation/scene > information) with per-category cool-downs; urgent warnings interrupt routine speech, and an interrupted navigation step is replayed once.
  • Shows a detector chip on the home screen (RF-DETR GPU or SSDLite CPU) so that a sighted helper can see which detector is active.

Privacy and safety by design

Camera images are processed in memory and are never written to disk, logs or the database; the history stores text messages only. The cloud description sends one image to a third party only after an explicit opt-in. Every spoken message is drawn from a fixed vocabulary that never states a distance and never says that a way is safe; the cloud description is filtered for the same words. The application states on its "How it works" screen that it is not a replacement for a cane, guide dog or human assistance.
